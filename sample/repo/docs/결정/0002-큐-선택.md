# 0002. 이벤트 큐로 Redis Streams를 써요

- 상태: 채택 (2025-01-20)

## 결정

이벤트 큐는 Redis Streams를 써요. 컨슈머 그룹으로 서버 여러 대가 나눠 처리하고, 처리하지 못한 메시지는 `XPENDING`으로 다시 가져와요.

## 왜 SQS가 아닌가

- 하루 이벤트가 10만 건 안팎이라 Redis 한 대로 충분했어요.
- 이미 세션 저장에 Redis를 쓰고 있어서 운영할 것이 늘지 않아요.
- 처리 순서를 가맹점 단위로 지키기 쉬웠어요.

하루 100만 건이 넘거나 여러 리전으로 가야 하면 다시 봐요.
