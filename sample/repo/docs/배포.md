# 배포와 롤백

## 배포

1. `main`에 머지하면 CI가 이미지를 만들고 스테이징에 자동으로 배포해요.
2. 스테이징에서 `npm run test:e2e -- --env staging`이 통과하는지 봐요.
3. 운영 배포는 사람이 해요: `npm run deploy:prod`. 배포 스크립트(`scripts/deploy.sh`)가 새 버전을 한 대씩 바꾸고, 각 서버의 `/healthz`가 200을 주면 다음으로 넘어가요.
4. 배포한 사람이 #paymint-deploy 채널에 버전과 변경 요약을 남겨요.

금요일 오후 4시 이후에는 운영 배포를 하지 않아요.

## 롤백

문제가 생기면 바로 이전 버전으로 되돌려요.

```bash
./scripts/deploy.sh production --rollback
```

`--rollback`은 직전에 성공한 이미지 태그로 다시 배포해요. DB 마이그레이션이 들어간 배포는 이것만으로 안 되고, 마이그레이션의 `down`을 먼저 돌려야 해요. 마이그레이션이 있는 배포는 PR 제목에 `[migration]`을 붙여서 알 수 있게 해요.
